# K = 24 development review

The user accepted K = 24 after reviewing the first development run and requested component comparisons on the same 1,440 datasets. This is an exploratory analysis of development outcomes already seen. The source for the candidate, the healthy families and the original study protocol remain at [the development freeze](https://github.com/amromeo/anchorRefine/commit/1c914bc3448a50f5327e522525cb448bfe836cea). Confirmation remains unopened during this review.

1. Run the three previously specified arms with K = 24. Enable only peak choice, starting grid nodes or search bounds, respectively. Use the same clarity check and original routine fitter seed for all three. Reuse the unchanged refineR baseline and full K = 24 fit from the [original development results](../results/stage2-development-45283676579/REVIEW.md). Verify the ordered routine and both panel hashes, the archived fits and the initial election. Include every assigned dataset, including fallback and failures.
2. For each arm report pre-check per-dataset loss minus the loss of unchanged refineR on the same Index. Native limits are primary and historical limits secondary. Clip each absolute endpoint z error at 5, then average the two endpoints. Charge an unreturned fit loss 5. Use the existing 20% split and report N, disease pattern and healthy family as marginal summaries and jointly crossed strata. Report counts and paired differences. Use the previous paired factorial-cell bootstrap, 2,000 samples with PCG64 seed 37000000. Show the descriptive result alone when a stratum contains fewer than two informative cells.
3. For the full K = 24 candidate, reconcile every fallback with the original 331. For each reporting stratum give the number assigned, number falling back, percentage and the recorded step and reason. The same tables can describe each ablation. Distinguish clarity failures in the initial election from a subsequent search that loses the selected basin.
4. Use the original Stage 1 check, both PIT seeds and the original two panels. Reuse the verified baseline and K = 24 fits and check their archived decisions. Compare the frequency and direction of guidance versus fresh-panel disagreement for each method. Report both each method's evaluable denominator and a direct comparison on cases evaluable for both. Panel replacement changes the observations and PIT randomization.
5. As a diagnostic on the original search, record the detected peak chosen by unmodified refineR on its first raw 512-bin density before trimming. Compare its grid index with the anchor winner on that same density for clear elections. Report agreement, disagreement and unclear elections separately. Compare observed arm errors within these groups. The review does not combine their outputs into a new candidate.
6. Record source and input hashes and repeat the runs in isolated R sessions on one runner and on a distinct runner using the existing tolerances. Preserve the primary estimates, decisions and audit records. Show the development review and one reasoned proposal. Adoption, freezing and execution of any amended candidate await user review.
