# Stage 2 development

The [approved protocol](../PROTOCOL.md#stage-2-approved-development-protocol) sets the two K candidates and their selection rule. Development uses 1,440 synthetic routine datasets, each with a guidance panel and an independent diagnostic panel of 40 screened healthy observations. The generator in this revision implements the development seed range only.

The [design manifest](development-design.csv) freezes the case ordering, truth, population SDs on the measurement scale, rounding increments and independent seeds. Each row represents one paired case across unchanged refineR and both full Stage 2 candidates. The inputs can be regenerated from that row and checked against their recorded hashes. `R/stage2-*.R` contains the derivative search. The vendored refineR implementation supplies its original pass-through and histogram cost. External reproducibility uses the same R and refineR libraries as Stage 0. The Stage 2 checker passes the actual measurement increment to the Stage 1 PIT and likelihood-ratio calculation.

The [development workflow](../.github/workflows/stage2-development.yml) verifies source and library hashes before fitting. Each job executes its own shard in two independent R sessions and a neighboring shard in a third session. The audit requires matching identities on the first host and a distinct boot ID for the separate-host audit. The merged primary per-case tables feed the report. The development report uses accuracy before the check to select K. Each formal release comparison checks both methods on the same guidance panel. The independent diagnostic panel is used only to measure anchor reuse.
